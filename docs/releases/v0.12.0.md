# rust-gvm v0.12.0

rust-gvm v0.12.0 adds typed Active Directory credential, verification, and
object-discovery operations; current structured Agent Control scheduling; and
confidential inventory-token issuance. It also preserves additional agent,
scanner, target, result, and report metadata and adds strict composition for
report-scoped result filters.

Callers upgrading from v0.11.1 should review the
[v0.12.0 migration guide](https://github.com/greenbone/rust-gvm/blob/v0.12.0/docs/v0.12.0-migration.md).
In particular, agent scheduler collections now contain `AgentSchedule` values,
and `ModifyAgentGroupRequest::new` requires the current nonempty group name.

Highlights:

- typed creation and partial modification of Active Directory credentials,
  saved or inline credential verification, and non-secret metadata projection;
- live directory-object discovery requests and typed counts, truncation,
  computer details, and optional target/task/configuration references;
- structured `AgentSchedule` entries with optional maximum randomized delay,
  agent-group delay handling, and scanner Agent Control defaults;
- typed, capability-discovered inventory-token issuance with redacted Debug and
  wire-trace output and rejection of empty successful token payloads;
- optional agent operating-system metadata and independent support-bundle
  anonymization and encryption selectors;
- target source provenance, result VT type, report task scan configuration,
  report application counts/threat, and corrected report fixtures;
- sensor scanner port-zero support matching current gvmd behavior;
- `compose_report_results_filter`, which validates caller filter fragments and
  appends independent report isolation plus endpoint-owned pagination;
- source-compatible serde defaults for newly projected optional fields and
  legacy string deserialization for agent schedules;
- release binaries for five targets, each with a SHA-256 checksum;
- the Linux amd64/arm64 mock-server image at
  `ghcr.io/greenbone/gvm-mock-server:v0.12.0` (no moving `latest` tag);
- CycloneDX JSON and XML SBOMs, an SBOM quality report, checksums, and Sigstore
  provenance for downloadable artifacts and the container image.

The AD, Agent Control, inventory-token, support-bundle, and filter additions
are qualified by pinned source evidence and deterministic tests. They do not
claim live LDAP, Agent Controller scheduling, token signing, support-bundle
privacy/cryptography, or live-gvmd qualification.

The release artifacts are built from the immutable `v0.12.0` tag and verified
against its exact qualified protected-main commit before publication completes.
