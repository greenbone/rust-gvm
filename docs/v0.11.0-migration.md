# Migrating from v0.10.0 to v0.11.0

`v0.11.0` adds a complete generic NVT-reference projection and enables explicit
agent-group membership clearing on compatible gvmd versions. It also replaces
the direct unmaintained `chrono` dependency and updates the SSH stack. The
project remains a pre-1.0 Technology Preview, so the minor-version change is
the compatibility signal.

Most callers can upgrade without changing existing requests or response access.
The existing CVE projection and public schedule types retain their behavior.
Applications that serialize NVT response models or clear agent-group membership
should review the details below.

## Generic NVT references

`gvm_gmp::responses::NvtReferenceEntry` is a new public response type with
`type_` and `id` strings. Result `NvtRef` and catalog/detail `Nvt` values now
contain `refs: Vec<NvtReferenceEntry>`:

```rust,ignore
for reference in nvt.refs.iter() {
    println!("{}: {}", reference.type_, reference.id);
}
```

Reference types are an open gvmd vocabulary. Compare `type_` only when an
application needs type-specific behavior, and retain unknown values when
forward compatibility matters. Attribute values are XML-decoded but otherwise
preserved; type spelling and case are not normalized.

The existing `NvtRef::cves` field is unchanged. It remains the compatibility
view for direct `<cve>` children and lower-case `type="cve"` references. Use
`refs` when the complete reference set is required. The aggregate
`get_report_vulns` projection remains outside this change.

Malformed `<ref>` elements without a non-empty `type` and `id` are ignored
without rejecting the enclosing response. With the `serde` feature, missing
`refs` fields deserialize to an empty vector, so serialized v0.10 values remain
readable. Newly serialized values include `refs`; update exact JSON snapshots
or closed schemas that enumerate every field.

Both `Nvt` and `NvtRef` were already `#[non_exhaustive]`, so downstream callers
cannot construct them with public struct literals. Ordinary field access and
wildcard destructuring remain source-compatible.

## Clearing agent-group membership

`ModifyAgentGroupRequest::agent_ids` now implements the complete
`CollectionUpdate` contract:

- `CollectionUpdate::Omitted` omits `<agents>` and preserves membership;
- `CollectionUpdate::Replace(non_empty)` emits repeated `<agent>` children;
- `CollectionUpdate::Clear` and `CollectionUpdate::Replace(Vec::new())` emit
  `<agents/>` to clear membership.

In v0.10, the clear forms failed client-side validation because released gvmd
versions treated `<agents/>` as a no-op. The new behavior requires a gvmd build
containing greenbone/gvmd#3251. Older servers can accept the request while
silently preserving the old membership, so deployments must upgrade gvmd
before relying on the clear result.

## Schedule date/time dependency

rust-gvm now uses `jiff` instead of `chrono` internally for schedule timestamp
validation and compact iCalendar conversion. `ScheduleTimestamp` remains a
string-backed public type; no `jiff` type is exposed. Accepted RFC 3339 forms,
UTC normalization, fractional-second truncation, pre-epoch values, leap
seconds, and malformed compact-timestamp rejection retain their v0.10 behavior.

Applications that depended on rust-gvm to bring `chrono` into their dependency
graph must declare their own date/time dependency. This does not affect normal
use of the rust-gvm schedule APIs.

## SSH and other dependencies

The optional SSH transport now resolves `russh` 0.65.1. It includes fixes for
agent lock-state rechecking after confirmation and for delaying `kex_done`
until server host-key verification succeeds. No rust-gvm API migration is
required.

The minimum supported Rust version remains 1.89. Tagged release artifacts keep
the v0.10 publication contract: five mock-server binary archives with
checksums, a Linux amd64/arm64 GHCR index, CycloneDX SBOMs and quality results,
and Sigstore provenance attestations. Only immutable `v`-prefixed tags are
published; there is no moving `latest` image.

## Result VT discriminator (#856)

`NvtRef::type_` now preserves the server's optional `<type>` string alongside
`type_metadata`. Match known values with `nvt.type_.as_deref()` and retain an
unknown-value fallback; do not assume an absent value means `nvt`. Existing
responses and serialized JSON without this field deserialize to `None`.
The serde field name is `type_`, consistent with other response discriminators.
Metadata remains opaque, decoded XML text, not parsed or rewritten JSON.

Evidence: gvmd `150a4cfad39d00f45ef147c35e1a5f27f415c8e9`, `src/gmp.c`
result NVT emission following f74799bc. This is static source-backed coverage,
not live-server qualification. Requests and version gates are unchanged.
Stateful mocks emit explicitly seeded `nvt_type`/`type_metadata` attributes;
absence is not synthesized. Default result fixtures represent classic NVTs.
